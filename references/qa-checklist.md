# HTML 生成物 QA 检查单与溢出修正阶梯

面向生成 HTML 作品（幻灯片、仪表盘、原型页面、演示文稿等）的 Agent 通用自检规范。本检查单提供渲染质量量化判据与梯级修复机制，确保生成物在视觉排版、无障碍可访问性与交互稳健性上达到交付级标准。

---

## 一、自检执行顺序

Agent 生成 HTML 作品后，必须严格遵循两阶段验证流：

```
[HTML 生成完成] 
      │
      ▼
┌──────────────────────────────────────────────┐
│ 1. 结构合宪性检查：tools/layout-check.mjs     │
│    核验每个 <section> 的 data-layout 标注     │
│    对比 references/layouts.json，严禁版式漂移  │
└──────────────────────────────────────────────┘
      │ 通过
      ▼
┌──────────────────────────────────────────────┐
│ 2. 渲染表现力检查：references/qa-checklist.md │
│    逐项核对「文本、布局、碰撞」三类检查项      │
│    若有渲染溢出，按「溢出修正阶梯」降级修复   │
└──────────────────────────────────────────────┘
      │ 通过
      ▼
[交付验收完成]
```

> **两者关系一句话说明**：  
> **`layout-check` 验证结构是否合宪（宏观版式登记不漂移），本检查单验证像素是否合格（微观渲染呈现无瑕疵）。**

## 二、三类核心检查

### 1. 文本检查（Typography & Text）

| 检查项 | 量化判定基准 | 违规隐患与自检动作 |
| --- | --- | --- |
| **溢出 / 换行 / 省略** | • 严禁未受控的文本溢出容器边缘或被无序截断。<br>• 中文排版必须遵守标点避头尾禁则（参见 `cjk-typography.md` T4）：行首不得出现 `，。！？：；、）》】”’`，行尾不得出现 `（《【“‘`。<br>• 单行省略必须三件套齐全：`overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`。<br>• 多行省略必须标准声明：`display: -webkit-box; -webkit-box-orient: vertical; -webkit-line-clamp: N; overflow: hidden;`，并确保父容器高度能容纳 $N \times \text{line-height}$，避免文字被水平切半。<br>• 含有长英文单词、代码标识符或 URL 的正文容器必须显式配置 `overflow-wrap: break-word;`。 | 缩放视口（如 320px、768px、1440px）自测正文断行：检查是否出现孤字成行、标点落于行首或单词撑裂容器。 |
| **色彩对比度** | • 所有正文、标题、辅助说明文字与实际背景的对比度必须 **$\ge 4.5:1$**（WCAG 2.2 AA 标准，本项目暗色模式统一要求 $\ge 4.5:1$，参见 `cjk-typography.md` T10）。<br>• 大号标题（$\ge 24\text{px}$ 或 $\ge 18.5\text{px}$ 粗体）严禁低于 $3:1$（强烈建议统一维持 $4.5:1$ 以上）。<br>• 对比度需覆盖 `:hover`、`:focus`、`:active`、禁用及暗色主题全态；半透明文字（`rgba` / `opacity`）必须先与背景色合成后再计算对比度。 | 重点核查暗色模式下的低对比度灰字（如 `#555` 在 `#121212` 下对比度仅约 2.8:1，属于典型违规）；占位符文字不得低于 $4.5:1$。 |
| **字号阶梯** | • 必须建立清晰可辨的字阶（Type Scale），常规文档以 `1rem`（16px）为基准。<br>• 标题阶梯严禁倒挂与跳级（如常规页面 h1: 32px / 2rem → h2: 24px / 1.5rem → h3: 20px / 1.25rem → 正文: 16px / 1rem；幻灯片遵循 `layouts.json` 专属阶梯，如 S01 标题 $\ge 72\text{px}$）。<br>• 任何正文或注释字号不得小于 $12\text{px}$（密集数据小注底线为 $11\text{px}$）。<br>• 严禁仅靠把正文字号加粗来充当大标题，必须使用层级递进的字号。 | 检查各级文本视觉层次，确保层级结构不依赖单一字重，页面主标题全局有且仅有 1 个 h1。 |

### 2. 布局检查（Layout & Structure）

| 检查项 | 量化判定基准 | 违规隐患与自检动作 |
| --- | --- | --- |
| **容器溢出** | • 页面视口或定高卡片内严禁出现非预期的滚动条（特别是水平滚动条 `overflow-x` 晃动）。<br>• 所有布局容器统一声明 `box-sizing: border-box;`，杜绝 `width: 100% + padding` 导致的撑大溢出。<br>• Flex 弹性子项在包含文字截断或表格时，必须声明 `min-width: 0;`（或 `min-height: 0;`），防止 Flex 容器被子内容撑破。 | 在浏览器中横向拖动视口，检查页面右侧是否出现白边；检查包含超长文本的 Flex/Grid 卡片是否把相邻列挤扁。 |
| **栅格错位** | • CSS Grid 与 Flex 多列布局的列宽基准线、列间隙（`gap`）必须几何严整对齐。<br>• 规避孤行现象（Orphan item）：如 3 列网格末尾单出 1 项时，不得被 `flex-grow: 1` 错误拉伸为通栏巨型卡片。<br>• 多卡片流式换行（`flex-wrap: wrap`）时，同级卡片应具备相同的 `min-width` / `max-width` 约束，卡片高度应保持等高对齐（`align-items: stretch`）。 | 缩放窗口检查断点变化，确认网格在换行折叠时排列是否整齐，内容长短不一时卡片底线是否错落杂乱。 |
| **层叠顺序 (z-index)** | • 建立语义化分层体系：底层背景（`z-index: 0`）→ 常规内容（`1–10`）→ 吸顶导航/粘性组件（`100`）→ 浮层与下拉菜单（`200`）→ 模态弹窗与遮罩（`500`）→ 全局吐司提示（`1000`）。<br>• 严禁滥用 `z-index: 99999` 等随意数值。<br>• 避免非预期的局部堆叠上下文（Stacking Context）：父级元素使用 `transform`、`filter`、`opacity < 1` 或 `will-change` 会锁死子元素，导致子级弹窗/下拉菜单无法覆盖外部同级元素。 | 滚动页面，测试下拉菜单（Dropdown）、气泡提示（Tooltip）展开时是否被后续的卡片或浮动 Footer 遮挡切断。 |

### 3. 碰撞检查（Collision & Spacing）

| 检查项 | 量化判定基准 | 违规隐患与自检动作 |
| --- | --- | --- |
| **元素重叠** | • 文档流中各视觉组件之间必须保持物理间隙，严禁无意的像素压盖。<br>• 严禁脱离文档流的绝对定位（`position: absolute`）遮盖相邻交互区域或文字。<br>• 负 margin 仅限用于已充分验证的装饰性重叠场景，严禁使文本与交互控件发生重叠碰撞。 | 动态注入最长测试文案，检查下方按钮、标签是否被上方文字块挤压或压盖。 |
| **点击目标 < 44px** | • 所有可交互控件（按钮、链接、图标按钮、Tab 标签、关闭叉号、复选框等）的物理可点击热区必须 **$\ge 44 \times 44\text{px}$**（遵循 WCAG 2.5.5 / 2.5.8 触控目标规范）。<br>• 若视觉图标本身较小（如 16px 或 20px 图标），必须通过 `padding`、`min-width` / `min-height` 或绝对定位伪元素 `::before` 扩充点击热区至 $\ge 44\text{px}$。 | 检查右上角弹窗关闭按钮、表格行内操作小图标等，核算其实际可点击几何包围盒尺寸。 |
| **贴边 < 8px** | • 容器内任何文本、图标、图像距离父容器边界或视口边缘的间隙必须 **$\ge 8\text{px}$**。<br>• 容器必须保留合理的呼吸感内边距（`padding: 8px` 为安全底线，卡片建议 `16–24px`），严禁文字或边框直接顶死边缘。 | 在小屏幕（320–375px）下检查卡片两侧与屏幕边界的间隙，检查按钮文字与按钮左右边框的内边距是否不足 8px。 |

## 三、溢出修正阶梯（吸收 guizang）

在固定视口（如幻灯片 16:9 比例视口）、定高看板或特定卡片内，内容超出容器承载时**严禁盲目胡乱修改**。  
必须先测量内容实际溢出量：  
$$\Delta = \max(\text{scrollWidth} - \text{clientWidth},\, \text{scrollHeight} - \text{clientHeight})$$

根据实测溢出量 $\Delta$，严格执行对应梯级操作。低梯级手段未用尽前，严禁越级跨入高梯级；溢出超标时，坚决回退重构。

```
┌────────────────────────────────────────────────────────────────────────┐
│ 梯级 1：实测溢出 1–40px   ──>  只调间距/内边距 (紧凑化空间)             │
├────────────────────────────────────────────────────────────────────────┤
│ 梯级 2：实测溢出 40–90px  ──>  压缩局部内容 (行距/字距/微调文案/裁次要)  │
├────────────────────────────────────────────────────────────────────────┤
│ 梯级 3：实测溢出 90–160px ──>  动内容结构 (删减元素/合并项目/重构组件)  │
├────────────────────────────────────────────────────────────────────────┤
│ 梯级 4：实测溢出 > 160px  ──>  版式选择错误，彻底放弃并重选 layout      │
└────────────────────────────────────────────────────────────────────────┘
```

### 梯级 1：实测溢出 1–40px（微量溢出）

*诊断：排版骨架与内容体量完全匹配，仅因内边距或间隙过宽导致轻微冒头。*

- **允许动作（Do）**：
  1. **收紧容器内边距**：如将卡片 `padding: 24px` 微调为 `20px` 或 `16px`。
  2. **收紧网格/弹性间距**：如将布局 `gap: 24px` 调整为 `16px` 或 `12px`。
  3. **微调元素外边距**：将标题下边距由 `margin-bottom: 20px` 调整为 `12px`，段落间距 `1em` 微调为 `0.75em`。
- **严禁动作（Don't）**：
  - ❌ **不得改动字号**（严禁为了 20px 溢出将 16px 正文改成 14px，破坏排版标尺）。
  - ❌ **不得删减任何文本或功能项**。
  - ❌ **不得隐藏或裁切视觉元素**。
  - ❌ **不得在外层容器直接设置 `overflow: hidden`** 掩耳盗铃。

### 梯级 2：实测溢出 40–90px（中度溢出）

*诊断：间距压缩已达 8px 底线但仍溢出，内容密度略高于容器舒适区。*

- **允许动作（Do）**：
  1. **压缩局部行距与字距**：将正文 `line-height: 1.7` 适度收紧为 `1.5`（严禁低于 `1.4`）；将大标题行高由 `1.3` 微调为 `1.15–1.2`；英文字距适度收紧。
  2. **裁剪次要修饰性元素**：移除纯装饰性背景图标、分割装饰线、次要角标（Badge）或冗余的修饰性阴影外框。
  3. **精炼局部文案措辞**：将冗长散文改写为凝练短句，压缩副标题字数。
  4. **次要说明文本受控截断**：仅对次要小字注释或补充说明配置 `line-clamp: 2` 省略，主干内容保持完整。
- **严禁动作（Don't）**：
  - ❌ **不得破坏核心内容结构**（例如要点列表原本有 3 条核心论点，严禁擅自删成 2 条）。
  - ❌ **不得大动网格列数**（例如原本 3 列网格不得强制折成 2 列导致布局畸形）。
  - ❌ **不得对核心标题、关键指标数字使用省略号截断**。
  - ❌ **不得将任何正文字号缩至 12px 以下**。

### 梯级 3：实测溢出 90–160px（重度溢出）

*诊断：局部微调已无法消除溢出，内容体量已逼近当前组件形态极限。*

- **允许动作（Do）**：
  1. **动内容结构**：合并同类项，精简次要分支；将长文本列表合并为精简键值对。
  2. **改变局部组件形态**：将松散宽大的卡片群（Card Grid）重构为紧凑型数据表格（Table）或紧凑列表（List）。
  3. **重排布局方向与列数**：将 4 列横向排列重组为 2×2 网格，或将横向图文左右并排改为垂直嵌套流式卡片。
- **严禁动作（Don't）**：
  - ❌ **不得以牺牲可读性为代价把字号降级到不可读区间**。
  - ❌ **不得违反 `references/layouts.json` 对该版式的核心契约**（例如 S03 要点页约束为 3–5 条，不得违规塞入 8 条长段落）。
  - ❌ **不得在非长页面容器（如固定演示幻灯片）中擅自增加内嵌滚动条**。

### 梯级 4：实测溢出 > 160px（结构性失配）

*诊断：溢出超 160px 说明版式选型从根本上无法承载当前信息体量，属于架构建模错误。*

- **允许动作（Do）**：
  1. **判定版式选择错误，彻底废弃当前布局**。
  2. **重选承载力匹配的 layout**：如将单一展示页推翻，重新选型为多栏对比版式或长篇滚动版式；幻灯片从单页要点页（S03）重选为分章节拆页（多张 Slide）。
  3. **拆分内容载体**：将单卡片/单屏拆分为两阶段视图（Step 1 + Step 2）或独立子屏重新生成。
- **严禁动作（Don't）**：
  - ❌ **绝对不得在错误版式上进行修补死循环**（严禁同时叠加缩字号 + 负 margin + 删减核心字句 + 强行隐藏溢出等拼接代码）。
  - ❌ **不得微调间距做无用功**（对 >160px 溢出调 padding 纯属无效计算）。

## 四、Footer 反模式与标准贴底方案

### 1. 为什么 `position: absolute; bottom: 0;` 贴底是错的？

很多 Agent 在处理页面或卡片底部页脚时，常采用绝对定位强制贴底：

```css
/* ❌ 典型反模式 */
.page-container {
  position: relative;
  min-height: 100vh;
}
.footer {
  position: absolute;
  bottom: 0;
  left: 0;
  right: 0;
}
```

**该写法存在的本质缺陷**：
1. **致命重叠与遮挡（Collision）**：`position: absolute` 会将 Footer 彻底移出正常文档流。一旦页面中间的主体内容动态变长或屏幕垂直空间缩小时，Footer 将直接悬浮覆盖在正文末尾、表单输入框或操作按钮之上，造成不可恢复的交互死锁。
2. **脆弱的魔法数字（Magic Numbers）**：为了防止覆盖，开发者被迫在主体容器上添加 `padding-bottom: 60px` 等固定数值；一旦用户缩放字号、Footer 内文案换行或增添链接，固定 padding 瞬间失效，重叠再次爆发。
3. **滚动截断**：在包含局部滚动条的子容器中，绝对定位 Footer 会切断滚动视野，严重破坏布局。

### 2. 标准解法：Flexbox 列容器 + `margin-top: auto`

现代 CSS 的标准规范做法是利用 Flexbox 列方向布局与自动外边距吸附机制：
- 父容器声明 `display: flex; flex-direction: column; min-height: 100vh`（或 `min-height: 100%`）。
- Footer 保持在正常文档流中，仅设置 `margin-top: auto`（或者主内容区设置 `flex: 1 0 auto`）。
- **空间充裕时（短内容）**：`margin-top: auto` 自动瓜分所有剩余垂直空间，将 Footer 优雅推至视口最底端。
- **空间受挤压时（长内容）**：Footer 自然跟随在正文之后向下顺延，绝对不会与正文发生任何物理碰撞。

### 3. 正反代码片段对比

#### ❌ 反面代码片段（Bad Pattern）

```html
<!-- ❌ 错误示范：绝对定位脱离文档流贴底 -->
<div class="bad-viewport">
  <header class="header">
    <h2>产品数据面板</h2>
  </header>
  <main class="bad-content">
    <div class="card">核心数据卡片 A</div>
    <div class="card">核心数据卡片 B</div>
    <div class="card">当数据卡片增多超出视口时，底部的绝对定位 footer 会直接压在此处！</div>
  </main>
  <footer class="bad-footer">
    <p>© 2026 Prototype Studio. All rights reserved.</p>
  </footer>
</div>

<style>
.bad-viewport {
  position: relative;
  min-height: 100vh;
  box-sizing: border-box;
}
.bad-content {
  /* 脆弱的防御性内边距：只要 footer 换行增高，立即被遮挡 */
  padding: 16px 16px 56px 16px;
}
.bad-footer {
  /* 严重反模式：脱离文档流 */
  position: absolute;
  bottom: 0;
  left: 0;
  right: 0;
  height: 48px;
  background: #f8fafc;
  border-top: 1px solid #e2e8f0;
  display: flex;
  align-items: center;
  padding: 0 16px;
}
</style>
```

#### ✅ 正面代码片段（Good Pattern）

```html
<!-- ✅ 正确示范：Flexbox 列容器 + margin-top: auto 安全贴底 -->
<div class="good-viewport">
  <header class="header">
    <h2>产品数据面板</h2>
  </header>
  <main class="good-content">
    <div class="card">核心数据卡片 A</div>
    <div class="card">核心数据卡片 B</div>
    <div class="card">无论此处置入多少内容，Footer 永远在文档流下方安全顺延，永不压盖。</div>
  </main>
  <footer class="good-footer">
    <p>© 2026 Prototype Studio. All rights reserved.</p>
    <div class="footer-actions">
      <button type="button" class="action-btn">系统帮助</button>
    </div>
  </footer>
</div>

<style>
.good-viewport {
  display: flex;
  flex-direction: column;
  min-height: 100vh;
  box-sizing: border-box;
}
.good-content {
  /* 内容区自然伸展，无需任何 magic padding */
  flex: 1 0 auto;
  padding: 16px;
}
.good-footer {
  /* 核心技巧：自动外边距吸纳所有剩余纵向空间，内容多时跟随向下 */
  margin-top: auto;
  min-height: 44px; /* 满足可交互区域与基准尺寸规范 */
  padding: 12px 16px;
  background: #f8fafc;
  border-top: 1px solid #e2e8f0;
  display: flex;
  align-items: center;
  justify-content: space-between;
}
.action-btn {
  min-height: 44px; /* 保证触控点击目标 >= 44px */
  padding: 0 12px;
}
</style>
```
